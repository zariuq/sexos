CHECKED OWNERSHIP ENVELOPES

Bell
----

src/sexbell.cesta enables Cesta's native ownership check for every function
body. Bell's mutable state remains one local Sexbell record containing inline
queues, policies, spam counters and diagnostic budgets. Helpers receive loans
of that state or of the particular field they need.

The generation helper receives a uint64_t pointer. A queue loan can therefore
remain live while the independent generation counter is updated. This is a
C interface change with a smaller memory footprint; no borrow ledger is
present in the executable.

find_policy returns a shared, nullable loan of the policy_table subobject.
derive_lane_first_proof writes a static, nullable string into its output slot.
Those lifetime declarations are checked against their bodies. The native
formatting, tick, reply and listener interfaces have explicit obligations;
their implementations remain outside Bell's checked body.

check-ownership reads Bell under GCC and Clang with every combination of the
three proof-profile flags. The resulting permission plans must agree. Source
controls must refuse overlapping call arguments, a returned local address,
a local address stored as static data and a false static-return declaration.

  make check-ownership CESTA=cesta

qualify-ownership additionally admits the emitted plans in Lean. It uses the
shared plan reader from the Cesta source tree and the existing MeTTapedia Lean
package; supply CESTA_SOURCE and LEAN_ROOT for those checkouts.

  make qualify-ownership CESTA=cesta CESTA_SOURCE=... LEAN_ROOT=...

The mathematical layer separates lifetime, access permission and release
authority. Its spatial law is parametric in the footprint representation;
contiguous C ranges and finite, potentially strided footprints are instances.
Bell uses the C range instance. Branches and loops are checked over permission
states, and actual function plans are joined by a proved module admission rule.

This is a permission/control proof. C-to-plan projection, ABI calculation,
printing, compilation, native calls and hardware remain separate tested or
conditional boundaries. The native surface admits declared reference fields
and bounded buffer views; arbitrary reference arrays, aggregate reference
results and all dynamic bounds are not yet supported. This port is not a
proof of arbitrary C or whole-system memory safety.

The ordinary build remains cesta build. Its readable C export builds without
Cesta. The existing Rust differential, sanitizer, plain-C identity and boot
checks remain necessary alongside ownership admission.

Sexstore
--------

The durable-page wrapper uses the same native permission model. Its page_view
returns an exact pointer/length view into its argument, and page_write_view
returns an exclusive view. Checked byte functions consume those views through
declared call signatures. Page offsets are guarded explicitly before indexing.
tests/sexstore_ownership.py checks actual GCC/Clang plans, the byte-codec plan,
source mutations and boundary executions.

Shell input
-----------

The input unit has eighteen entry functions from current pinned Rust.
ShellInputContext embeds the canonical ShellChromeContext and borrows Atlas
and Surfaces separately. The shell root owns app custody, desktop dimensions
and delivery state. Selecting a Linen object uses the existing Models view;
there is no second exclusive pointer into the same Models object. Helpers pass
scoped subviews through typed calls. Keyboard routing, motion and button
handling remain separate functions with the same externally observed order.

Remaining legacy adapters bind every context field to the corresponding shell
state subobject and reject a mismatched binding. Thirteen diagnostic bindings
and the two app-focus helpers instead use actual checked scoped contexts.
Activation queries may change state; focus is observed after the query, matching
Rust's evaluation order. Peer implementations preserve references and do not
retain usable loans. Snapshot publication retains the
legacy address-word ABI; an address is not a memory grant. The current display
server has no handler for that snapshot opcode, so the host descriptor test
does not establish cross-domain snapshot delivery.

tests/silk_shell_input_differential.py executes the eighteen current Rust
bodies plus the real focus and dimension helpers. Custody predicates and atomic
acquire adapters are real; activation replies, desktop shortcuts and remaining
subsystem operations are scripted. It compares output, state, interaction
payloads, custody records, tombstones and descriptors, including the remaining
legacy ABI bindings. All sixteen Input feature combinations are supported.
The declared profile bounds the window table at 64 and
the published snapshot at 16 descriptors. Stable partition replaces the
temporary vector and sort while preserving order for unique window identities.
The tombstone insertion checks its cursor before indexing. Separate corrupted-
cursor controls require the defined failure path, including with sanitizers;
removing the guard must be detected. Independent controls check that a full
cursor queue retains only the latest coordinates, fatal rejection ends retry,
failed admission does not advance the send counters, pending custody rejects
input, wide successor bounds do not overflow, and failed palette execution
keeps the palette open. A query that changes focus detects stale observations.
Dynamic dimension subtraction uses defined Rust-compatible wrapping. Invalid
clamp bounds follow the defined failure path, including zero and negative
dimensions; INT32_MIN subtraction is exercised under the sanitizers. The root
initializer must set the current desktop defaults (1280 by 800) before Input
is used, then accept dimensions through the validated display path.
The private dimension getter takes a read-only atomic-word view. A getter
that accepts the whole mutable Input context grants many unrelated regions;
narrow views keep its declared permission footprint equal to its actual read.

tests/silk_shell_input_ownership.py checks the actual permission plans and
refuses read-only fields used for writes, a stored local address, aliasing
under an exclusive field borrow and an uninitialized nested context. Lean admission
is enabled by the same qualify-ownership command as Bell and Sexstore.

Shell Atlas
-----------

The current Atlas unit has forty-four entry functions and eight shared helpers.
ShellAtlasContext carries exclusive references to Atlas, Chrome and Models.
Labels return as fixed-size value records. Context references are neither stored
in those values nor replaced by temporary local addresses. Native adapters bind
the references to the corresponding shell state records; the compatibility
label-output ABI still requires its declared sixteen-byte destination.

tests/silk_shell_atlas_ownership.py checks both compiler plans, all current
entries and the same read-only, dangling-field, exclusive-alias and uninitialized
context controls. Optional admission uses the actual emitted plan. The native
peer contracts remain separate obligations. Runtime state/effect comparisons
and independent malformed-snapshot controls are described in ATLAS.txt.

Shell custody and Chrome
------------------------

The custody archive checks eighteen functions against a generated immutable
BOOT association table. Entries carry scalar identities and inline metadata;
queries return fixed-size values, not references to temporary lookup records.
Read-only receivers and exclusive mutation receivers remain distinct at calls.
The native binding to held kernel custody is still an external obligation.

The Chrome archive checks ninety-five current functions, the two Rect
methods and fifty-two helpers. SilkBar geometry adds two checked functions. Its context has explicit reference fields for Chrome,
Models, Input, proof state and app custody. The native atomic adapters and remaining subsystem
peers are declared obligations. Corrected generation behavior, its retained-
identity theorem and remaining caller obligations are recorded in CHROME.txt.

tests/silk_shell_custody_ownership.py and tests/silk_shell_chrome_ownership.py
check both compiler plans and their source refusal controls. Their Lean mode
admits the actual emitted function plans. They do not turn the remaining
unchecked shell callers or native hooks into a whole-system ownership proof.

The viewport module admits its actual delivery, layout and geometry plans.
Document and Spindle queues use distinct value-record types around shared
state. Captured notices are data; the native held-route send remains an
explicit obligation. Queue mutation during a live exclusive loan and writes
through a read-only receiver are refused.

Native C layout, shares and obligations
---------------------------------------

Every (native "...") fragment in src/ is laid out by one rule, .clang-format,
applied by clang-format 21.1.8 through tools/native_format.py. The tool
refuses any result that differs from the original in more than whitespace
and C line splices, and --check lists sources that do not follow the rule.
When the rule was first applied, all 101 GCC and 101 Clang outputs of
cesta build and all four AArch64 images were byte-identical before and after.
Tests that mutate exported C or Cesta source match their patterns through
tests/layout_text.py, which ignores layout at token boundaries.

tools/native_census.py reports three shares in non-whitespace bytes:
structured Cesta, native C read by the ownership check, and native C the
check does not read. Every unit with native function bodies carries
(ownership (check-all)); --check fails for one that does not. A definition
the check refuses is named with what its code relies on,
(unchecked (NAME...) CONTRACT... (obligation "...")): the body is not read,
its callers are checked against the declared contract, and the plan records
it as a foreign obligation. Units whose native text is only declarations
count as read by the check when a checked unit includes the header they
generate.

The Browser's regex compiler and PNG decoder are fully checked. The PNG
helpers read the source, scratch and pixel records through offsets into
their inline arrays rather than raw byte pointers. The script core checks 72
of its definitions and HTML 7; their named definitions read or write
(pointer, length) ranges, return interior pointers into the workspace tables
or use do-while loops. Across the kernel, AArch64, shell bindings, network
and probes, the refused definitions are named with their unit's obligation:
inline assembly, volatile and MMIO access, integer-derived addresses, records
whose reference fields have no contracts yet, and calls into interfaces
without foreign contracts. The native profile does not yet admit dynamically
sized views as function parameters or do-while statements, and its loop rule
does not recognize an unconditional loop with no normal exit; each of those
extensions, and field and foreign contracts for the shell and network
bindings, turns a group of named definitions into checked code.
